# Установка, обновление и восстановление

## Универсальное правило

Не удаляйте приложение перед обновлением. Скачайте **полный архив новой версии**, распакуйте и запустите **тот же установщик**, что и при первой установке. Сценарий определяет установленную версию и использует её окружение Python.

## Windows (сетевой ZIP, x64)

- Новая установка: `INSTALL-WINDOWS.cmd` → проверка Windows 10/11 x64 → локальный Python, Pandoc и зависимости → тестовая конвертация → ярлыки.
- Обновление: тот же `INSTALL-WINDOWS.cmd` или `UPDATE-WINDOWS.cmd` → используем `venv313` → предварительная проверка кода → резервная копия исходников и оформления → замена → реальный smoke test → восстановление резервной копии при сбое.
- При неудачной загрузке или проверке зависимостей работающий код не меняется. Старые резервные копии лежат в `%LOCALAPPDATA%\DocForge\code-backup-*`.
- Не смешивайте каналы установки: для ZIP-бутстрапа используйте ZIP-обновление, для EXE Inno Setup — EXE из того же канала после его тестирования.
- Удаление: `windows\UNINSTALL.cmd`. Документы, находящиеся вне каталога DocForge, не удаляются. Перед удалением сохраните пользовательские настройки при необходимости.

## Linux

- Новая установка: `./INSTALL-LINUX.sh` (или `./install.sh`).
- Обновление: `./INSTALL-LINUX.sh` или `./UPDATE-LINUX.sh`. Установщик направляет уже установленную программу в безопасное обновление; update при отсутствии программы запускает полную установку.
- Обновление предварительно проверяет Qt/зависимости и компилирует новые исходники во временной папке, только затем заменяет код. В случае сбоя восстанавливает предыдущий код.
- Резервные копии: `~/.local/share/docforge/.backup-*`.
- Перезапустите главную программу/зону после обновления; если меню Nautilus не видно, выполните `nautilus -q`.
- Удаление: `./uninstall.sh`. Сохраните пользовательские настройки при необходимости.

При неполадках приложите лог, версию ОС и скриншот: [TROUBLESHOOTING.md](TROUBLESHOOTING.md).
